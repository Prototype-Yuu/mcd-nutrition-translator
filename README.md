# 麦门翻译官 · mcd-nutrition-translator

> **别给我毫克，给我几碗饭。**
>
> 一个麦当劳中国 MCP Skill：把餐品的六个营养数字，翻译成你立刻能感知的东西。

你点了一单巨无霸套餐，官方给了你六个数：550 千卡、25 克蛋白、1000 毫克钠……

**然后呢？** 1000 毫克钠是多少？多还是少？

这个 Skill 的答案是把数字翻成人话：

---

### 巨无霸 + 中薯 + 中可乐

**换成你能感知的：** 约 5 碗米饭 ｜ 约 5 个鸡蛋的蛋白质 ｜ 约 3 克盐

| 指标 | 数值 |
| --- | --- |
| 热量 | 1040 千卡 |
| 蛋白质 | 29 克 |
| 脂肪 | 46 克 |
| 碳水化合物 | 127 克 |
| 钠 | 1280 毫克 |
| 钙 | 140 毫克 |

**这一单是：** `碳水主力` · `顶饱型`

**一句提醒：** 钠这块占了今天不少，晚上挑清淡一点的就行。

<sub>以上为麦当劳官方营养标注值；生活类比为本项目约定的参照换算，不构成营养或医疗建议。</sub>

---

## 目标用户

**大学生和刚工作的年轻人**，尤其是：

- 想吃麦当劳但看不懂营养表的人 ——「1000 毫克钠到底算多吗」
- 想控制一下但不想记流水账的人 —— 设目标、打卡、算百分比，坚持不过三天
- 只想快速知道「我这一单大概是什么构成」的人 —— 不想被教育，只想被翻译

设计前提是**默认用户没有营养学基础，也不想学**。所以不要求填任何表单、不要求设任何目标、不要求连续使用。

## 快速开始

```bash
git clone https://github.com/Prototype-Yuu/mcd-nutrition-translator.git
cd mcd-nutrition-translator

# 1. 申请 Token：https://open.mcd.cn/mcp 手机号登录 → 控制台 → 激活 → 复制
export MCD_MCP_TOKEN="你的 token"

# 2. 看接口通了没（应返回 33 个工具）
python3 scripts/mcp_client.py list | head -40

# 3. 用真实营养数据跑一张餐卡（需要先准备好 items JSON）
python3 scripts/mealcard.py --input tests/fixtures/card-simple.json --format md

# 4. 有条件的配平模式
python3 scripts/mealcard.py --input tests/fixtures/card-solve.json --solve --format md

# 5. 跑测试
python3 -m unittest discover -s tests
```

零第三方依赖，Python ≥ 3.9，`git clone` 后直接能跑。

## 三层能力，懒人停在第 0 层就够

| 层 | 用户说什么 | 你得到什么 | 需要设目标吗 |
| --- | --- | --- | --- |
| **L0 即时报数** | "我想吃巨无霸加中薯" | 一张餐卡：生活类比 + 六项数值 + 中性外号 + 一句提醒 | 不用 |
| **L1 一句话目标** | "想吃 600 卡以内，蛋白多点" | 2–5 个符合条件的组合 + 最划算的一单 | 一句话 |
| **L2 全天累计** | "早上吃了碗面，晚上还能吃啥" | 已摄入 + 剩余额度 + 组合建议 | 一句话 |

大部分场景停在第 0 层。第 1、2 层是给想多走一步的人准备的，不是必选项。

## 使用示例

**问「这个多少卡」**

> 用户：巨无霸多少热量？
> → 调用 `list-nutrition-foods`，对齐名称，返回：550 千卡 · 约 1.5 碗米饭（按本项目参照换算）

**问「这单怎么样」**

> 用户：我点了巨无霸、中薯、中可乐，这套怎么样？
> → 出餐卡，标签 `碳水主力` `顶饱型`，一句提醒指向晚上怎么配

**问「400 千卡以内能吃什么」**

> 用户：中午想吃 400 卡以内，蛋白多点
> → L1 模式：取菜单 → 对齐营养 → 穷举组合 → 返回符合条件的组合表

**问「这个含花生吗」**

> → **不调用任何工具**，直接说明官方接口没有配料与过敏原数据，引导看包装 / 问门店 / 顾客关怀热线 400-920-0205。原因见 [references/dietary-boundaries.md](references/dietary-boundaries.md)

## 能做什么，不能做什么

这张表是这个项目最重要的部分。

| 能力 | 状态 | 依据 |
| --- | --- | --- |
| 六项营养数值（能量/蛋白/脂肪/碳水/钠/钙） | ✅ 官方数据 | `list-nutrition-foods` |
| 换算成米饭/鸡蛋/盐 | ✅ 本项目约定值，已公开基准 | [references/analogy-basis.md](references/analogy-basis.md) |
| 按热量/蛋白/钠/预算凑组合 | ✅ 确定性穷举，可复现 | `scripts/mealcard.py --solve` |
| 门店、菜单、算价、优惠券、下单 | ✅ 走官方 MCP | 见 `references/tools-catalog.md` |
| 过敏原 / 配料表 | ❌ **接口没有这个数据** | 33 个 Tool 里零字段 |
| 素食 / 清真判定 | ❌ 无配料、无认证标识 | 同上 |
| 糖分细分 / 升糖指数 | ❌ 只有总碳水 | 同上 |
| 疾病饮食建议 | ❌ 非医疗产品 | 只给数值，不给结论 |
| 政策 / 退款 / 发票 | ❌ 无知识库 | 转官方渠道 |
| 跨品牌比较 | ❌ 明确不做 | 赛事内容合规要求 |

**为什么把"不能做"写在这么显眼的地方**：因为一个说"我查不到"的助手，比一个敢猜的助手有用。这类工具最容易犯的错，是拿常识把缺失的数据补成一个看起来合理的数。

## 这不是一个"健康助手"

它不做的事，和它做的事一样重要：

- 不给"健康/不健康"的判词
- 不打分、不评级、不说"适合/不适合"
- 不说教、不列待办清单、不催你打卡
- 不和其他品牌比较

外号只描述**构成**（`碳水主力`、`蛋白担当`、`钠值选手`），提醒只指向**动作**（"晚上挑清淡一点的就行"）。判断留给你自己。

## 工程设计

```
mcd-nutrition-translator/
├─ SKILL.md                     # 技能入口：路由 + 三条铁律 + 文案红线
├─ references/
│  ├─ tools-catalog.md          # 33 个 Tool 分组与验证状态
│  ├─ analogy-basis.md          # 类比基准 + 它的来源等级 + 可能错在哪
│  └─ dietary-boundaries.md     # 拒答话术 + 禁止词表
├─ scripts/
│  ├─ mcp_client.py             # 纯标准库 Streamable-HTTP 客户端
│  ├─ normalize.py              # 名称归一化 + 对齐匹配器（三态输出）
│  └─ mealcard.py                # 合计 / 类比 / 外号 / 一句提醒 / 穷举求解
├─ tests/                       # 35 个 unittest，含"故意错配"反例
├─ data/                        # 脱敏快照与对齐覆盖率报告
└─ examples/                    # 真实数据的餐卡示例
```

**四条设计约束**

1. **真实字段名只出现在适配器一处。** 接口改字段名，只改 `normalize.py` 的候选键表，全链路不受影响。
2. **`null` 不参与求和，但一定出现在缺失清单里。** 静默丢数据是这类项目最典型的错误。
3. **份量基准不明就拒绝给合计。** 宁可返回"算不了"（退出码 2），不给一个看起来合理但错的数。
4. **求解用穷举不用启发式。** `C(25,2)=300`，秒级完成，且两次运行结果完全一致 —— 可复现比优雅重要。

### 数据对齐：这个项目真正的难点

官方的营养表和门店菜单**没有共同的键**：

- `list-nutrition-foods` 按**餐品名称**给数据，没有编码
- `query-meals` 按**餐品编码**给菜单，没有名称

要算合计，只能用名称把它们对上。而两边的命名并不一致（菜单带规格后缀、营养表带份量说明），所以对齐本身就是一个需要显式处理的问题，不是一个可以技巧性绕过的细节。

本项目的做法是把这件事**摊开**：匹配器输出 `matched` / `ambiguous` / `unmatched` 三态，每个匹配都记录命中层级（精确 / 去规格 / 别名 / 包含 / 相似）和分数，`ambiguous` 一律不自动取值。实测覆盖率见 [data/alignment-coverage.md](data/alignment-coverage.md)。

## 已知限制

- 命中率受官方命名差异影响，未被收录的餐品会显示"未收录"，不估算。
- 类比换算是本项目约定值，不是官方数据，误差可达 ±30%，基准已公开可核。
- 依赖真实 MCP Token；无 Token 时只能跑 fixture，不能取实时数据。
- 不处理支付：`create-order` 只返回支付链接，不做代付。
